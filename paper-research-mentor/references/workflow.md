# Operational workflow

## Intake without an interview bottleneck

Accept PDFs, saved plain text/Markdown, readable publisher HTML extracted through browsing, a DOI/URL, or a series. Main paper, appendix, code and project notes are separate sources with roles `main`, `supplement`, `code`, `project`, `external`. Supply version/canonical URL only when known. Verify metadata titles against the paper.

Default is full analysis plus discussion preparation. Infer focus from the request. Missing background can be taught; missing project facts remain unknown. Do not ask an intake questionnaire. For inaccessible inputs, finish other work and name the actual obstacle.

Initialize a library, ingest sources, and start a run with their IDs. Register only relevant project documents. Save necessary excerpts locally, not unrelated private repositories.

## Reading passes

1. Coverage: inventory ALL PDF pages, warnings, section candidates, bibliography boundary, supplements and unavailable artifacts. Establish readability page by page. Numbered/Chinese headings and two-column order need inspection.
2. Argument: read problem, method, results and limitations as a connected scientific story; distinguish motivation from tested hypotheses.
3. Mechanism: follow each central component and mathematical step; explain prerequisites, a worked example, dimensions and counterexamples where useful.
4. Evidence: inspect central figures/tables/equations visually, map claims to support and alternatives. Read every substantive section even if not quoted.
5. Transfer: bounded writing patterns and project ideas; compare papers only after individual reading.
6. Review: recheck central source passages, numbers and conditions against the report; validate/export and disclose unresolved items.

Long papers are read in section batches with actual page coverage in run notes. Do not silently truncate the corpus. Extraction != reading != semantic verification.

## Output and completion

Create a run-local overview linking substantive deep reading, math/figures, reproduction when applicable, writing, transfer and discussion. Omit irrelevant modules with reasons, not filler. Include ledger/JSON exports.

`analysis`: `in_progress`, `complete`, `partial`. `verification`: `pending`, `partial`, `verified`. Participation is independently computed. `verified` requires reviewed evidence, and existing image files for visual evidence. Disclose limitations and pages not verified.

Default chat shows a short map and one consequential question; full files remain accessible. Under no-question instructions save prompts, leave them pending, and finish the analysis. No timers or recurring reminders without request.

Resume from run state and the latest genuine response. Correct report claims with a correction note; never silently rewrite the user's earlier belief.
